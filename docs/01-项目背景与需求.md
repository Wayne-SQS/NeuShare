## 一、项目背景

### 1.1 现状分析

东北大学（NEU）在校师生规模庞大，每学期都有大量课程同步产生各类学习资料，包括但不限于课程笔记、历年真题、实验报告、课件 PPT、复习提纲、考研资料等。这些资料在学生群体中具有高度的流转和复用价值，是学习过程中不可或缺的辅助资源。

然而，目前校内资料分享主要依赖以下几种非正式渠道：

- **QQ 群 / 微信群**：以班级或课程为单位建立，资料分散在多个群聊中，新人无法回溯历史资料，群文件有时效限制且难以检索。
- **百度网盘 / 阿里云盘**：依赖分享链接，链接易失效，资料缺乏结构化分类与描述，无法进行关键词搜索。
- **线下口口相传**：高年级学长向低年级学弟学妹口口传递，覆盖面窄，资料更新滞后。
- **个人博客 / GitHub 仓库**：少数同学自发整理，维护成本高，覆盖范围有限。

### 1.2 现有方式的痛点

| 痛点 | 具体表现 |
|------|---------|
| 资料散落 | 同一份资料可能存在于多个群、多个网盘链接中，重复且无序 |
| 难以搜索 | 缺乏统一的元数据（课程、分类、标签），无法按关键词、分类快速定位 |
| 无法互动 | 看完资料后无法评论、提问、纠错，资料质量无法沉淀反馈 |
| 缺乏激励 | 上传者无任何正向反馈（点赞、收藏、关注），分享意愿逐渐降低 |
| 质量参差 | 没有审核机制，错误、过时、低质量资料混入其中 |
| 多端割裂 | PC 端查阅方便但移动端体验差，移动端便捷但功能受限 |

### 1.3 项目定位

NeuShare 旨在打造一个面向东北大学师生的**校园学习资料分享平台**，通过统一的 Web 端与鸿蒙移动端，将分散的学习资料汇聚到结构化、可搜索、可互动、可激励的平台上，形成「上传—审核—浏览—互动—激励」的良性闭环。

平台核心价值：

1. **资料结构化**：通过分类、标签、课程关联，让资料可被快速检索与定位。
2. **互动社区化**：评论、点赞、收藏、关注、社区帖子，让资料分享从单向传输变为双向交流。
3. **多端覆盖**：Web 端满足深度查阅与上传，鸿蒙端满足移动场景下的浏览与互动。
4. **质量可控**：管理员审核机制过滤低质与违规内容，保障平台资料整体质量。
5. **激励可持续**：点赞数、收藏数、关注数等数据指标，为上传者提供持续的正向反馈。

## 二、用户角色与使用场景

### 2.1 角色定义

平台共定义三类用户角色，权限逐级递增：

| 角色 | 权限范围 |
|------|---------|
| **学生** | 注册登录、上传/搜索/浏览/评论/点赞/收藏资料、发帖讨论、关注其他用户、接收通知、编辑个人信息 |
| **教师** | 在学生权限基础上，可上传官方教学资料（标注来源为「教师官方」），资料审核优先级更高 |
| **管理员** | 在教师权限基础上，可审核资源、管理用户（启用/禁用/删除）、管理评论、管理轮播图、管理服务卡片、查看平台统计数据 |

### 2.2 典型使用场景

**场景一：期末复习找资料**
学生在期末前需要某门课程的历年真题与复习提纲。打开 NeuShare 移动端，通过分类或关键词搜索定位到目标资料，查看详情页确认内容质量后下载，并在评论区留下感谢或提问。

**场景二：学霸分享笔记**
某同学整理了一份高质量的课程笔记，上传到 NeuShare，填写课程、分类、标签、简介。资料进入待审核状态，管理员审核通过后对外发布。其他同学点赞、收藏、评论，上传者收到通知，获得持续的正向反馈。

**场景三：教师发布官方资料**
某课程教师将课件 PPT、实验指导书上传到平台，标注为「教师官方」来源。学生通过该来源标签快速识别权威资料，避免被错误版本误导。

**场景四：社区讨论**
学生在学习社区发帖讨论某门课程的难点、考研经验、项目合作等。其他同学点赞、收藏、评论，形成主题化的学习交流空间。

**场景五：管理员审核**
管理员登录后台，查看待审核资源列表，对资料内容、版权、质量进行判断，通过或驳回（驳回需填写理由）。同时可管理用户状态、轮播图、服务卡片，维护平台整体秩序。

## 三、功能需求

### 3.1 用户认证与个人信息

- **注册**：用户名、密码、昵称、学院、年级等基本信息注册。
- **登录**：用户名 + 密码登录，成功后返回 JWT Token 与用户信息。
- **JWT 鉴权**：所有需登录接口通过 JWT Token 校验身份，Token 失效后需重新登录。
- **修改密码**：需校验原密码，通过后更新为新密码（BCrypt 加密存储）。
- **编辑个人信息**：修改昵称、头像、学院、年级等。
- **角色权限**：通过 JWT 拦截器区分普通用户与管理员，`/api/admin/**` 路径额外校验 `role="admin"`。

### 3.2 资源管理

- **上传资源**：通过 FormData 上传文件，填写标题、课程、分类、标签、简介、资源类型（文档/视频/图片等）。
- **搜索资源**：支持关键词搜索、分类筛选、标签筛选，可按热度（`like_count`）或时间（`create_time`）排序。
- **分类浏览**：支持父子层级分类（`category` 表 `parent_id` 字段），按学院、课程类型等维度组织。
- **资源详情**：展示完整信息，自动累加浏览量，展示评论树、相关推荐。
- **文件下载**：已发布资源支持下载（视频类型支持在线播放）。
- **资源所有权**：仅上传者本人或管理员可编辑/删除资源，非上传者且非管理员不可操作。
- **审核流程**：新上传资源默认状态为「待审核」（0），管理员审核通过后变为「已发布」（1），驳回为「已驳回」（2，需填写 `reject_reason`）。

### 3.3 社区互动

- **帖子 CRUD**：用户可发帖（标题、正文、标签、图片、附件），编辑或删除自己的帖子。
- **评论（树形）**：资源评论与帖子评论均支持树形结构（`parentId` 父子关系），可回复、可删除（评论者或管理员）。
- **点赞**：资源与帖子均支持点赞，`resource_like` / `post_like` 表防重复刷赞。
- **收藏**：资源与帖子均支持收藏，`favorite` / `post_favorite` 表记录收藏关系。
- **关注**：用户可关注其他用户，`follow` 表唯一约束防重复关注，关注后可查看关注列表与粉丝列表。
- **通知系统**：审核结果、评论回复、关注、收藏、点赞均推送通知，通知类型分为 `comment` / `follow` / `like` / `favorite` / `audit`，支持已读、未读数量、批量已读、删除。

### 3.4 管理后台

- **统计数据**：平台概览（用户数、资源数、帖子数、互动数等），分类/类型/来源分布，热门排行，趋势图表（ECharts 5）。
- **用户管理**：用户列表（关键词搜索）、启用/禁用用户、删除用户（级联清理关联数据）。
- **资源审核**：待审核资源列表，通过/驳回（驳回需理由），删除任意资源。
- **评论管理**：查看全部评论，删除任意评论。
- **轮播图管理**：增删改查轮播图，切换启用状态（用于首页 Banner 展示）。
- **服务卡片管理**：增删改查服务卡片（用于首页推荐位），切换启用状态。

## 四、非功能需求

### 4.1 安全性

- **JWT 认证**：所有非公开接口需携带有效 JWT Token，拦截器统一校验。
- **BCrypt 密码加密**：用户密码使用 BCrypt 强哈希存储，数据库不存明文。
- **CORS 限制**：后端 CORS 仅允许 `localhost` 来源，不使用通配符 `*`，防止跨域滥用。
- **资源所有权校验**：资源更新/删除、帖子更新/删除、评论删除均校验操作者是否为作者或管理员。
- **防重复操作**：点赞、关注通过数据库唯一约束防止重复刷数据。
- **公开接口加固**：`/api/resource/list` 与 `/api/post/list` 允许传入 `status` 参数，但非管理员强制覆盖为 `1`（仅已发布），防止越权访问未审核内容。
- **敏感配置注入**：数据库密码、JWT 密钥通过环境变量 `${DB_PASSWORD}`、`${JWT_SECRET}` 注入，不硬编码。

### 4.2 性能与可靠性

- **计数器定时校准**：每日凌晨 3 点定时任务校准 `like_count`、`favorite_count`、`comment_count` 等冗余字段，防止并发场景下计数漂移。
- **冗余字段实时更新**：`resource_count` / `follower_count` / `following_count` / `total_likes_received` 等字段在业务操作时原子更新，定时任务兜底校准。
- **毛玻璃性能分级**：鸿蒙端根据设备性能与滚动状态动态降级毛玻璃效果（HIGH/LOW/NONE），避免低端设备掉帧。
- **本地 JSON 兜底**：鸿蒙端所有数据获取操作先用本地 JSON 数据渲染首屏，再异步刷新 API 数据，保证弱网下的可用性。

### 4.3 响应式与多端适配

- **Web 端自适应**：基于 Element Plus 栅格与 CSS 媒体查询，适配桌面与平板。
- **鸿蒙端 5 级断点**：XS / SM / MD / LG / XL 五级断点（基于 `window` API + `mediaQuery` + `display` 三通道架构），覆盖小屏手机到大屏折叠屏。
- **点击热区**：鸿蒙端所有可交互元素热区 ≥ 40vp，满足触控友好。

### 4.4 视觉与主题

- **双主题系统**：亮色（靛蓝毛玻璃，多彩渐变背景）与深色（极简黑白，唯一强调色为白色）使用完全不同的视觉语言，非简单颜色反转。
- **主题动态切换**：所有页面通过 `@StorageLink('isDarkMode')` 订阅主题，使用 `ColorTokens` 动态取值。
- **沉浸式状态栏**：鸿蒙端 `EntryAbility` 设置透明状态栏，与页面内容融为一体。

### 4.5 离线能力

- **收藏/历史记录本地持久化**：鸿蒙端基于 `PreferencesStore` 将收藏与浏览历史持久化到本地，离线可查看。
- **本地 JSON 兜底**：资源列表、轮播图、分类等核心数据本地预置 JSON，断网时仍可浏览首屏。

## 五、技术选型与理由

### 5.1 Web 前端

| 技术 | 选型理由 |
|------|---------|
| **Vue 3 (Composition API)** | 组合式 API 逻辑复用性强，`<script setup>` 语法简洁，生态成熟，适合中小型团队快速迭代 |
| **Vite 5** | 基于 ESM 的极速冷启动与 HMR，开发体验远优于 Webpack；生产构建 Rollup 产物体积小 |
| **Element Plus 2.6** | 企业级组件库，表单、表格、对话框、上传等组件齐全，开箱即用，降低 UI 开发成本 |
| **Pinia** | Vue 3 官方推荐状态管理，API 简洁，TypeScript 友好，替代 Vuex |
| **Vue Router 4** | 官方路由方案，支持嵌套路由、导航守卫，配合 `beforeEach` 实现权限控制 |
| **Axios** | 主流 HTTP 客户端，拦截器机制便于统一处理 Token 注入与错误处理 |
| **ECharts 5** | 国产可视化库，图表类型丰富，管理后台统计数据可视化首选 |

### 5.2 后端

| 技术 | 选型理由 |
|------|---------|
| **Spring Boot 3.3.7** | Java 生态最成熟的后端框架，自动配置、Starter 依赖、Actuator 监控一体化，社区活跃 |
| **MyBatis-Plus 3.5.13** | 在 MyBatis 基础上增强，提供 BaseMapper 通用 CRUD、条件构造器、分页插件，大幅减少样板代码 |
| **MySQL 8** | 关系型数据库事实标准，支持 JSON 字段、窗口函数、CTE，满足平台数据存储与复杂查询需求 |
| **JWT (jjwt 0.13.0)** | 无状态 Token 认证，前后端分离架构下天然适配，避免 Session 共享问题 |
| **BCrypt** | 密码哈希算法自带盐值，计算成本可调，抵御彩虹表与暴力破解 |

### 5.3 移动端

| 技术 | 选型理由 |
|------|---------|
| **HarmonyOS NEXT API 22** | 华为纯血鸿蒙原生 API，无 AOSP 兼容包袱，性能与体验最优；适配国产化趋势 |
| **ArkUI + ArkTS** | 声明式 UI 范式，状态驱动渲染，开发效率高；ArkTS 在 TypeScript 基础上增强类型安全 |
| **双模块 HAR 架构** | `common` 模块封装主题、网络、工具等公共能力，`entry` 模块承载业务页面，模块化清晰，便于复用与维护 |

### 5.4 数据库与构建工具

| 技术 | 选型理由 |
|------|---------|
| **Maven** | Java 项目标准构建工具，依赖管理稳定，插件生态丰富 |
| **npm + Vite** | 前端包管理与构建标准组合，与 Vue 3 生态深度集成 |
| **DevEco Studio** | 华为官方鸿蒙 IDE，集成 SDK 管理、模拟器、调试、签名发布全流程 |

## 六、数据模型概览

平台数据库 `neushare` 共 14 张表，覆盖用户、资源、互动、社区、运营五大领域：

| 领域 | 表 | 说明 |
|------|-----|------|
| 用户 | `user` | 用户基本信息（用户名、密码哈希、昵称、头像、学院、年级、角色、状态） |
| 资源 | `resource` | 资源主体（标题、课程、分类、标签、文件路径、类型、状态、审核理由、计数冗余字段） |
| 资源 | `category` | 资源分类（含 `parent_id` 父子层级） |
| 互动 | `comment` | 资源评论（树形，`parent_id`） |
| 互动 | `favorite` | 资源收藏关系 |
| 互动 | `resource_like` | 资源点赞关系（唯一约束防重复） |
| 互动 | `follow` | 用户关注关系（唯一约束防重复） |
| 互动 | `notification` | 通知（含 `triggerUserId` 触发者、类型、已读状态） |
| 社区 | `post` | 帖子（标题、正文、标签 JSON、图片 JSON、文件 JSON、计数冗余字段） |
| 社区 | `post_comment` | 帖子评论（树形） |
| 社区 | `post_like` | 帖子点赞关系 |
| 社区 | `post_favorite` | 帖子收藏关系 |
| 运营 | `banner` | 首页轮播图（图片、链接、启用状态、排序） |
| 运营 | `form_card` | 首页服务卡片（标题、内容、链接、启用状态） |

**预置种子数据**：8 个用户（密码 BCrypt 加密）、12 个分类、133 条资源、20 条帖子、59 条评论、12 条收藏、3 张轮播图、119 条课程链接等，便于开发与演示。

## 七、项目目标与边界

### 7.1 项目目标

1. **统一资料入口**：成为东北大学师生查找与分享学习资料的首选平台。
2. **多端一致体验**：Web 端与鸿蒙端功能对齐，体验一致，覆盖学习全场景。
3. **良性社区生态**：通过点赞、收藏、关注、通知等机制，激励用户持续贡献高质量资料。
4. **可运营可维护**：提供完善的管理后台与统计数据，支撑平台长期运营。

### 7.2 项目边界

本期项目聚焦于校园学习资料分享的核心闭环，以下内容**不在本期范围**：

- 实时音视频直播 / 在线课堂
- 资源付费交易 / 积分体系
