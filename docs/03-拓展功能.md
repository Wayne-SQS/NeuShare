## 1. 鸿蒙端响应式布局系统

### 功能描述

为适配手机、折叠屏、平板等不同尺寸的鸿蒙设备，平台在 `common` 模块中实现了五级断点响应式布局系统 `BreakpointSystem`，让同一套代码在不同屏幕上自动调整网格列数、字体大小与间距。

### 技术实现

断点阈值定义（单位 vp）：

| 断点 | 范围 |
|------|------|
| XS | < 320 |
| SM | 320 - 600 |
| MD | 600 - 840 |
| LG | 840 - 1440 |
| XL | >= 1440 |

采用三通道架构保证可靠性：

- `window.getWindowSize()`：取初始尺寸
- `mediaQuery`：监听尺寸变化，响应式更新
- `display`：兜底方案

页面通过 `@StorageLink('currentBreakpoint')` 订阅断点变化，使用 `BreakpointType<T>` 按断点取值，替代冗长的 `if/else` 阶梯判断：

```typescript
@StorageLink('currentBreakpoint') currentBreakpoint: string = BreakpointTypeEnum.SM;

// 网格列数随断点变化
private columns: number = new BreakpointType<number>({
  sm: 1, md: 2, lg: 3, xl: 4
}).getValue(this.currentBreakpoint);
```

### 价值

使一套 ArkUI 代码同时覆盖直板机、折叠屏、平板三类设备，避免为不同尺寸维护多套布局；同时规避了 `display.isFoldable()` / `display.getDefaultDisplaySync()` 在非折叠屏模拟器上不可靠的问题。

## 2. 双主题配色系统

### 功能描述

平台提供亮色与深色两套完全独立的视觉主题，通过 `ColorTokens` 统一管理色板，支持手动切换与跟随系统。

### 技术实现

两套主题采用完全不同的视觉语言，并非简单的颜色反转：

- **亮色（Light）**：靛蓝毛玻璃主色 `#4A6BFF`，多彩渐变背景（粉/紫/蓝/青），`backdropBlur(40)` 玻璃卡片
- **深色（Dark）**：极简黑白 `#0E0E10` 背景，唯一强调色 `#FFFFFF`，零彩色，全靠强度、粗细、边框区分层级

全局通过 `@StorageLink('isDarkMode')` 订阅主题状态，组件使用 `ColorTokens.PRIMARY(isDark)` 等动态方法取值：

```typescript
@StorageLink('isDarkMode') isDarkMode: boolean = false;

build() {
  Text('NeuShare')
    .fontColor(ColorTokens.PRIMARY(this.isDarkMode))
    .backgroundColor(ColorTokens.BACKGROUND(this.isDarkMode))
}
```

全站 60+ 处组件硬编码颜色已全部替换为 `ColorTokens` 引用，确保主题切换时视觉一致。

### 价值

亮色主题营造活力校园氛围，深色主题提供专注沉浸的夜间阅读体验；统一色板消除了硬编码颜色带来的维护负担，新增组件只需引用 `ColorTokens` 即可自动适配双主题。

## 3. 毛玻璃性能分级

### 功能描述

毛玻璃（Backdrop Blur）是平台核心视觉语言之一，但在低端设备或滚动场景下容易导致掉帧。`BlurPerformance` 模块根据设备能力与交互状态动态降级毛玻璃强度。

### 技术实现

三级毛玻璃策略：

| 级别 | 值 | 触发条件 |
|------|-----|------|
| `HIGH` | 40 | 高端设备 + 静止状态 |
| `LOW` | 20 | 中端设备 |
| `NONE` | 0 | 低端设备 或 滚动中 |

通过两个 `AppStorage` 键协同工作：

- `isScrolling`：滚动状态标志
- `blurLevel`：当前毛玻璃级别

`onScrollFrameBegin` 回调中更新滚动状态（使用静态缓存避免每帧查询 `AppStorage`），`GlassCard` 通过 `@StorageProp('blurLevel')` 订阅响应式降级：

```typescript
@StorageProp('blurLevel') blurLevel: number = BlurLevel.HIGH;

build() {
  Column() { /* ... */ }
    .backdropBlur(this.blurLevel)
}
```

### 价值

在保证高端设备视觉体验的同时，避免低端设备因毛玻璃计算导致的卡顿；滚动时自动降级为零毛玻璃，确保列表滑动流畅，兼顾美观与性能。

## 11. HttpClient 401 竞态修复

### 功能描述

并发请求同时返回 401 时，旧版基于 `boolean` 标志的实现会触发多次登录页跳转，造成体验混乱。本次修复使用 Promise 锁保证只跳转一次。

### 技术实现

```typescript
private static unauthorizedPromise: Promise<void> | null = null;

private static async handleUnauthorized(): Promise<void> {
  if (this.unauthorizedPromise) {
    return this.unauthorizedPromise;
  }
  this.unauthorizedPromise = this.doRedirectToLogin();
  try {
    await this.unauthorizedPromise;
  } finally {
    this.unauthorizedPromise = null;
  }
}
```

错误信息在跳转后通过 `AppStorage` 或路由参数保留，登录成功后回填到对应表单，避免用户重新输入。

### 价值

消除并发 401 导致的多次跳转与状态错乱；错误信息保留机制减少用户重复输入，提升登录流程的容错性。

## 12. 定时计数器校准

### 功能描述

`CounterCalibrationTask` 每日凌晨 3 点执行，校准各类计数器字段，防止并发场景下的计数漂移。

### 技术实现

- **校准字段**：`like_count`、`favorite_count`、`comment_count`
- **冗余字段**：`resource_count`、`follower_count`、`following_count`、`total_likes_received`
- **双保险**：定时校准 + 实时原子更新（`UPDATE ... SET count = count + 1`）

```java
@Scheduled(cron = "0 0 3 * * ?")
public void calibrate() {
  resourceMapper.calibrateLikeCount();
  resourceMapper.calibrateFavoriteCount();
  // ...
}
```

### 价值

实时原子更新保证高频写入场景下的性能，定时校准兜底修复潜在的数据不一致；冗余字段避免频繁 `COUNT` 查询，提升列表接口响应速度。

## 13. 统一动画系统

### 功能描述

全站动画遵循统一标准，避免不同页面动画时长与曲线不一致带来的割裂感。

### 技术实现

- **默认标准**：`Curve.EaseOut`，`duration: 200ms`
- **例外场景**：
  - `SplashPage`：500ms，营造戏剧性开屏
  - 呼吸动画：1500ms，慢节奏循环
  - 过渡动画：300ms
- **页面转场**：统一 `pageTransition`
  - `Enter`：300ms，`EaseOut`，slide Right
  - `Exit`：250ms，`EaseIn`，slide Left
- **入场动画**：4 个 Tab 页 + 8 个子页面补充淡入动画
- **定时器泄漏修复**：`CommunityPage`、`EmptyState` 的 `setInterval` 在 `aboutToDisappear` 中清理

```typescript
aboutToDisappear() {
  if (this.timer) {
    clearInterval(this.timer);
    this.timer = null;
  }
}
```

### 价值

统一的动画标准让全站交互节奏一致，提升专业感；定时器泄漏修复避免长时间使用后的内存增长与卡顿。

## 14. 离线缓存与本地兜底

### 功能描述

针对弱网与离线场景，平台在鸿蒙端构建了多层缓存机制，保证核心功能在无网络时仍可用。

### 技术实现

- **ResourceService**：本地 JSON 兜底 + API 刷新。首屏先用本地 JSON 渲染，再异步拉取 API 数据
- **FavoriteService**：在线/离线双通道，本地缓存与云端同步
- **PreferencesStore**：键值持久化，存储收藏 ID、浏览历史、年级、主题等
- **mergeLocalFavoritesToCloud**：离线期间产生的收藏自动同步到云端

```typescript
// 首屏本地兜底
async loadResources() {
  this.resources = await this.loadLocalJson();   // 立即渲染
  const remote = await ResourceApi.list();        // 异步刷新
  if (remote) this.resources = remote;
}
```

### 价值

弱网环境下首屏仍可秒开，离线时用户操作不丢失；联网后自动同步，保证数据最终一致。该机制显著提升校园网络波动场景下的用户体验。
