# NeuShare 产品视角分析

> 不是功能盘点，是回答一个问题：**如果它要真的活下去，缺什么、该砍什么、下一步做什么。**
> 分析时间：2026-09-17

---

## 0. 一句话结论

**技术完成度远高于产品完成度。** 工程层面做到了课程项目的天花板（三端、14 张表、双主题、5 级断点、完整的工程细节），产品层面卡在一个所有 UGC 平台都会死的地方：**没人回答"资料从哪来"**。

这不是贬低——作为作品集项目它完成度很高；但如果要讲"我做了一个产品"，当前这套叙事撑不住，必须补上产品判断。

---

## 1. 先定性：它现在到底是什么

| 维度 | 现状 |
|------|------|
| 数据 | 8 个种子用户、133 条资源、20 条帖子、59 条评论——**全部预置，无真实流量** |
| 用户 | 无真实注册用户，无留存曲线，无行为数据 |
| 运营 | 无运营主体（社团？实验室？学院？），无人审核、无人运维 |
| 定位 | 课程作品 / 个人作品集项目 |

**定性：它是一个"功能完整的作品集项目"，不是"运营中的产品"。** 这个定位不丢人，但面试时不能混着讲——说"我做了个平台"会被追问"多少用户"，说"我完整实现并设计了一个校园资料平台，完成了从需求到三端落地的全过程"就站得住。

---

## 2. 需求验证：痛点成不成立

文档里列的六个痛点，逐个验：

| 痛点 | 成立吗 | 判断 |
|------|:---:|------|
| 资料散落 | ✅ 真 | QQ 群资料确实无法回溯 |
| 难以搜索 | ✅ 真 | 群文件无元数据，这是真痛点 |
| 无法互动 | ⚠️ 半真 | 用户要的是"资料对不对、全不全"，不是社交 |
| 缺乏激励 | ⚠️ 半真 | 上传者确实没反馈，但**点赞收藏是极弱激励** |
| 质量参差 | ✅ 真 | 但有审核机制就要付出规模成本 |
| 多端割裂 | ❌ 弱 | 学生找资料 90% 在手机上，但手机上是 QQ/微信，不是浏览器 |

**最关键的一点被漏掉了**：真正的痛点不是"没地方存资料"，而是 **"不知道谁有、不敢确定是不是今年的、不知道这位老师考什么"**。资料分享的瓶颈从来是**发现和信任**，不是存储和检索。

---

## 3. 竞品：你真正的对手是谁

不是 CSDN、不是百度文库，是这三个：

| 对手 | 优势 | 你的机会 |
|------|------|---------|
| **课程 QQ 群** | 零摩擦、资料自然沉淀、全员已在 | 不可检索、不可跨年级复用、群文件有时效 |
| **百度网盘分享** | 存量大、习惯强 | 链接失效、无结构化、无质量信号 |
| **学长私聊** | 信任度最高、最精准 | 不可规模化、覆盖面窄 |

结论很明确：**NeuShare 的胜算在"跨年级沉淀 + 可检索 + 质量信号"，而不是"存储"。**

这意味着一个反直觉的产品决策：**不要让用户上传文件，要让用户"登记"他已经存在的资料**。把网盘链接、群文件、课程资料登记进来，打上"课程 / 教师 / 年份 / 题型"的元数据。摩擦从"整理并上传"降到"贴个链接选几个标签"，供给量可能差一个数量级。

---

## 4. 核心诊断：供给侧死穴

资料平台是双边市场。需求侧天然存在（每个学生期末都要找资料），**供给侧没有答案**：

> 一个学生凭什么要花时间整理笔记、填分类标签、等审核，去换几个陌生人的点赞？

现在的答案是"点赞 + 收藏 + 关注"——这是社交产品的激励，不是工具产品的激励。在冷启动阶段（没人看、没人赞），这套激励等于零。

**这是整个产品最大的结构性风险。** 所有功能都建在"有资料"这个前提上，而这个前提没有保障。

### 闭环逐环体检

| 环节 | 现状 | 状态 |
|------|------|:---:|
| **上传** | 学生主动整理上传，摩擦力最大 | 🔴 供给断裂 |
| **审核** | 全量人工前置审核 | 🟡 规模瓶颈 |
| **浏览** | 仅标题/描述 LIKE 匹配 | 🟡 核心价值薄弱 |
| **互动** | 评论 + 关注 + 通知 | ⚪ 需求存疑 |
| **激励** | 点赞 / 收藏 / 粉丝数 | 🔴 激励失效 |

逐条说：

- **上传**：成本高、收益低，冷启动时归零。这是第一堵墙。
- **审核**：133 条能人工审，1 万条就崩。而且审核主体不存在——老师没义务审，学生管理员没权威。**前置审核会直接掐死供给**，建议改「先发后审 + 举报下架 + 上传者信用分」。
- **浏览**：一个"帮你找资料"的产品，搜索只有 LIKE 关键词，这是把命门交给了最弱的实现。**搜索不准，其他一切功能都是零。**
- **互动**：工具型产品里做社交三件套（关注/粉丝/通知），ROI 很低。用户来是为了拿资料走，不是为了交朋友。
- **激励**：点赞数对上传者的激励接近于零，尤其在没有流量时。

## 5. 投入错配：外围精致，核心薄弱

把已有功能按「投入 vs 用户价值」摊开看：

| 功能 | 投入 | 用户价值 | 判断 |
|------|:---:|:---:|------|
| **搜索（LIKE）** | 低 | **极高** | ❌ **严重错配**——命门却是最小投入 |
| **内容供给机制** | 无 | 极高 | ❌ **缺失** |
| **审核效率** | 人工 | 高 | ⚠️ 不可扩展 |
| 双主题 + 毛玻璃 + 动画系统 | 高 | 中 | ⚠️ 体验加分，但不解决核心 |
| 5 级断点响应式 | 中 | 中低 | ⚠️ 设备渗透率决定上限 |
| 考研攻略 / 院校导航 / 网课 / 开源库 | 中 | 低 | ⚠️ **内容填充，无壁垒**（任何人一下午能爬出来） |
| 通知 + 关注 + 社区帖子 | 中高 | 中低 | ⚠️ 工具产品里的社交功能 |
| 鸿蒙服务卡片 | 低 | 低 | ⚠️ 依赖鸿蒙设备渗透率 |
| 离线缓存 / 本地 JSON 兜底 | 中 | 中 | ✅ 校园弱网真实存在，合理 |
| 定时校准计数器 | 低 | 中 | ✅ 工程严谨性，面试可讲 |

**这张表是最值得反思的东西**：视觉系统、动画、双主题做到了极致，而"搜索"这个决定生死的功能只用了 LIKE。这是典型的"把时间花在有成就感的地方"，而不是"花在最重要的地方"。

（当然，作为学习项目，把视觉和工程细节做深是合理的——那是练技术的地方。但要清楚：**技术练到了，产品没练到。**）

## 6. 三端策略：一个必须想清楚的矛盾

Web + 鸿蒙双端，从**产品**角度看：

- 学生群体鸿蒙 NEXT 设备渗透率极低，几乎不构成真实用户入口
- 真实的产品决策应该是 Web（主）+ 移动端 H5 或小程序（补）
- 鸿蒙端 14 个页面、5 级断点、服务卡片——投入产出比不高

但对你**个人**：鸿蒙端是极强的简历差异化，全国做 HarmonyOS NEXT 全套三端项目的学生凤毛麟角。

**我的判断：这个选择是对的，但叙事要自洽。** 别讲"因为学生都用鸿蒙"（一戳就破），要讲：

> "三端里 Web 承担真实可用性验证，鸿蒙端是面向国产终端生态的技术预研——我把一次开发多端部署、5 级断点、状态管理、离线兜底这些能力在真实项目里完整跑了一遍。"

这样既诚实，又保住了技术价值。

## 7. 如果真要让它活：产品路线

### 北极星指标

不要看注册数和资源数（都是虚荣指标）。用：

> **周活跃用户中，成功获取 ≥1 份可用资料的比例**

这个指标同时反映供给（有没有）和需求（找不找得到），一个指标卡住两边。

### 只做三件事的话

**1. 搜索（命门）**
- 语义检索：LLM 向量搜索，解决"描述不清楚但知道要什么"
- 结构化筛选：`课程 + 授课教师 + 学年 + 资料类型（真题/笔记/课件/实验）`，比关键词有用得多
- 场景入口："2024 数据结构（张XX）期末真题"——按课程聚合，而不是按资源聚合

**2. 供给侧（死穴）**
- **PGC 冷启动**：找各课程学委/助教批量导入历史资料，或先爬校内公开课件、往年试题，平台自己先有料
- **把上传改成登记**：支持直接贴网盘链接、支持拍照上传手写笔记、支持从 QQ/微信转发进来
- **强激励**：上传换下载券（下载消耗券），形成内部流通。文档里把积分体系排除在边界外——但积分恰恰是 UGC 平台的供给侧引擎，这个取舍值得重新考虑

**3. 审核提效**
- 前置人工审核 → **先发后审 + 举报下架 + 上传者信用分**
- 自动初筛：敏感词、重复检测、文件可用性检测（外链是否失效）

### 场景化切入

不要做全品类资料站。做**高频场景**：

- **期末周**：按课程聚合的"期末救命包"，考前两周集中爆发
- **考研季**：真题 + 院校 + 经验贴的组合

场景化才能让低频行为变高频，也更容易冷启动（在正确的时间点推给正确的人）。

## 8. AI 智能体在产品上的真实价值

不是"加个聊天框"，它应该对准前面诊断出的两个产品问题：

| 产品问题 | AI 的解法 |
|---------|----------|
| 搜索不准（命门） | 语义检索 + 查询改写，解决"说不清楚要什么" |
| 供给侧不足（死穴） | AI 把已有资料"变现"：自动生成摘要、自动归类打标签、自动判断资料质量、自动回答"这份资料讲了什么" |

**但要警惕一个陷阱**：库里没东西的时候，AI 助手毫无价值，只会放大"平台没内容"的事实。**先有料，再上 AI。**

顺序应该是：PGC 冷启动 → 语义搜索 → AI 助手 → 工作流编排。

## 9. 商业模式与可持续性

校园项目基本没有商业模式，但要能回答"谁来运维"：

- 现实路径：挂靠学生社团 / 实验室 / 软件学院课程平台，作为**课程设计作品集平台**
- 如果不做资料分享，另一个更有供给侧动力的方向是：**软院学生项目作品集平台**——学生有展示自己作品的强动机（为了求职），而展示作品的意愿 >> 分享笔记的意愿。这个方向的供给问题天然被解决了

## 10. 面试怎么讲产品思考

### 会被问到的问题

1. "目标用户是谁？场景是什么？"
2. "用户为什么不用 QQ 群要用你的？"
3. "资料从哪来？怎么冷启动？"
4. "有多少用户？"（诚实回答：种子数据，作品集项目）
5. "为什么做鸿蒙端？"
6. "如果继续做，下一步做什么？"
7. "你砍掉了什么？为什么？"

### 主动交代的「我知道但没做」清单

主动说边界，比被追问出来强得多：

- 全文检索（当前 LIKE，已规划 Elasticsearch / 向量检索）
- 积分与激励体系（已识别为供给侧关键，本期划出边界）
- 推荐算法（当前基于年级/收藏的简单规则）
- 审核自动化（当前人工，规模上是瓶颈）
- 真实用户验证（当前为种子数据，未做用户访谈与灰度）

### 一个自洽的定位表述

> "NeuShare 是一个面向校园学习资料场景的全栈实践项目。我在其中负责从需求分析、数据建模到三端实现的完整链路，重点解决了资料结构化、审核流程和多端一致体验三个问题。项目当前处于作品集阶段，未做真实用户验证；如果继续推进，优先级最高的三件事是语义搜索、供给侧冷启动机制和审核提效。"

这段话同时体现了：完整链路能力、清醒的自我认知、产品优先级判断。**比"我做了一个校园资料分享平台"强十倍。**

## 附：一句话定位改写

现在的定位：「校园学习资料分享平台」——太泛，没有记忆点。

更锋利的版本：

> **"东大版 '按课程找真题' —— 输入课程和老师，找到往年真题、笔记和课件。"**

把"分享平台"改成"找资料的工具"，把"泛校园"改成"课程级精准定位"，价值主张立刻清晰。
