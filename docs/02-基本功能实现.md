## 一、用户认证系统

### 1.1 功能概述

用户认证是平台所有需登录操作的基础。系统采用 **JWT（JSON Web Token）** 作为无状态认证方案，密码使用 **BCrypt** 强哈希算法加密存储，避免明文风险。

### 1.2 注册流程

用户提交注册表单，包含以下字段：

| 字段 | 说明 |
|------|------|
| username | 登录用户名（唯一） |
| password | 明文密码（后端 BCrypt 加密后入库） |
| nickname | 昵称（展示用） |
| college | 所属学院 |
| grade | 年级 |

后端 `AuthController.register` 接收 JSON body，校验用户名唯一性后，调用 `BCryptUtil.encode()` 加密密码并写入 `user` 表。

### 1.3 登录流程

登录接口 `POST /api/auth/login` 接收 `{username, password}`，验证流程：

1. 根据用户名查询用户记录
2. 使用 `BCryptUtil.matches()` 校验密码
3. 校验通过后由 `JwtUtil.generateToken()` 生成 JWT
4. 返回 `{token, user: UserVO}` 给前端

前端将 token 存入 Pinia store 和 localStorage，后续请求通过 Axios 拦截器自动附加 `Authorization: Bearer <token>` 请求头。

### 1.4 JWT 拦截器

`JwtInterceptor` 在 `WebMvcConfig` 中注册，对 `/api/**` 路径生效，分三层权限控制：

| 路径类别 | 处理逻辑 |
|---------|---------|
| 公开白名单 | `/api/auth/login`、`/api/resource/list`、`/api/resource/detail/**`、`/api/banner/list`、`/api/category/list`、`/api/post/list`、`/api/post/detail/**`、`/api/stats/overview`、`/api/user/*` 等直接放行 |
| 需登录路径 | 其他所有 `/api/**`，校验 token 有效性，失败返回 401 |
| 管理员路径 | `/api/admin/**` 额外校验 `role="admin"`，否则返回 403 |

### 1.5 个人信息与密码

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/auth/info | 获取当前登录用户信息 |
| PUT | /api/auth/info | 更新个人信息（JSON body：nickname/avatarUrl/college/grade） |
| PUT | /api/auth/password | 修改密码（**params 传参**：oldPassword、newPassword） |

> 注意：修改密码接口使用 `@RequestParam` 接收参数，前端必须通过 `params` 而非 `data` 提交，这是后端约定的统一规范之一。

## 二、资源管理

### 2.1 资源创建

`POST /api/resource/create` 接收 **FormData** 格式数据，支持上传文件及元信息：

- 文件类型：`document`（文档）、`video`（视频）、`code`（代码）、`other`（其他）
- 文件保存到 `uploads/` 目录（由 `file.upload.path` 配置）
- `FileUploadUtil` 处理文件存储并返回访问 URL

### 2.2 资源列表与搜索

`GET /api/resource/list` 支持多维度筛选：

| 参数 | 说明 |
|------|------|
| pageNum / pageSize | 分页参数（非 page/size） |
| status | 资源状态（非管理员强制覆盖为 1） |
| categoryId | 分类筛选 |
| keyword | 关键词搜索（标题/描述） |
| sortBy | `hot`（按 like_count DESC）或 `new`（按 create_time DESC） |

响应字段：`records`（资源列表）、`total`（总数）。

### 2.3 资源详情

`GET /api/resource/detail/{id}` 返回 `ResourceVO`，关键字段：

- `uploadNickname`、`uploadUsername`、`uploadAvatar`：上传者信息（非 authorName）
- 每次访问自动 `view_count + 1`

### 2.4 文件下载与视频播放

- **文件下载**：`uploads/` 目录通过 Spring 静态资源映射为 `/files/**`，前端直接通过 URL 访问
- **视频播放**：B 站外链资源使用嵌入播放器 `player.bilibili.com/player.html?bvid=<BVID>`，在 WebView/iframe 中加载

### 2.5 资源审核

| 状态值 | 含义 |
|-------|------|
| 0 | 待审核 |
| 1 | 已发布 |
| 2 | 已驳回（含 `reject_reason` 字段说明原因） |

管理员通过 `PUT /api/admin/resource/audit`（params：id、status）执行审核操作，审核结果通过通知系统推送给上传者。

### 2.6 点赞与收藏

- `resource_like` 表通过唯一约束（user_id + resource_id）防止重复点赞
- `favorite` 表同理防止重复收藏
- 计数器 `like_count`、`favorite_count` 采用原子更新（`UPDATE ... SET like_count = like_count + 1`），避免并发问题
- 每日凌晨 3 点由 `CounterCalibrationTask` 定时校准计数器与实际记录数

### 2.7 资源相关 API 清单

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | /api/resource/list | 公开 | 资源分页列表 |
| GET | /api/resource/detail/{id} | 公开 | 资源详情 |
| GET | /api/resource/hot | 公开 | 热门资源 |
| GET | /api/resource/search | 公开 | 搜索资源 |
| POST | /api/resource/create | 登录 | 创建资源（FormData） |
| PUT | /api/resource/update | 登录 | 更新资源（JSON body） |
| DELETE | /api/resource/delete/{id} | 登录 | 删除资源（所有者或管理员） |
| POST | /api/resource/like/{id} | 登录 | 点赞 |
| DELETE | /api/resource/like/{id} | 登录 | 取消点赞 |
| GET | /api/resource/like/check/{id} | 登录 | 检查是否已点赞 |
| POST | /api/favorite/add | 登录 | 收藏（params: resourceId） |
| DELETE | /api/favorite/remove | 登录 | 取消收藏（params: resourceId） |
| GET | /api/favorite/check | 登录 | 检查是否已收藏 → {isFavorite} |

## 三、分类与标签

### 3.1 分类体系

`category` 表通过 `parent_id` 字段支持父子层级结构，预置 12 个分类覆盖东北大学主要学院与学科方向。

`GET /api/category/list` 返回全部分类（含父子层级），前端可据此构建级联选择器或树形菜单。

### 3.2 标签系统

`resource` 表的 `tags` 字段存储 JSON 数组字符串，预置 12 种标签：

- 专业学习、408 考研、考研数学、期末速成、AI 大模型、课程设计、实验报告、历年真题、学习笔记、参考资料、其他、原创整理

### 3.3 标签搜索

`ResourceMapper.xml` 中通过 `tags LIKE CONCAT('%', #{keyword}, '%')` 实现标签模糊匹配，与标题/描述搜索组合使用，提升检索召回率。

## 四、评论系统

### 4.1 资源评论

`comment` 表采用 **树形结构**（`parent_id` 自关联），支持多级回复。`CommentVO` 关键字段：

| 字段 | 说明 |
|------|------|
| nickname | 评论者昵称 |
| avatarUrl | 评论者头像 |
| content | 评论内容 |
| children | 子评论列表（递归构建） |

### 4.2 帖子评论

社区帖子使用独立的 `post_comment` 表，结构与资源评论一致，同样为树形结构。删除帖子评论时级联删除子评论，并原子递减帖子的 `comment_count`。

### 4.3 评论操作 API

| 方法 | 路径 | 传参方式 | 说明 |
|------|------|---------|------|
| GET | /api/comment/list/{resourceId} | 路径参数 | 资源评论树 |
| POST | /api/comment/add | **params** | 添加评论（resourceId、content、parentId?） |
| DELETE | /api/comment/delete/{id} | 路径参数 | 删除评论（所有者或管理员） |
| POST | /api/post/comment/add | **params** | 添加帖子评论（postId、content、parentId?） |
| DELETE | /api/post/comment/delete/{id} | 路径参数 | 删除帖子评论 |

## 五、社区帖子

### 5.1 帖子 CRUD

`PostController` 提供帖子全生命周期管理，所有写操作使用 **JSON body** 传参：

| 字段 | 类型 | 说明 |
|------|------|------|
| title | String | 标题 |
| content | String | 正文 |
| tags | JSON 字符串 | 标签数组，如 `["AI","课程"]` |
| imageUrls | JSON 字符串 | 图片 URL 数组 |
| files | JSON 字符串 | 附件信息数组 |

前端读取时需对 tags/imageUrls/files 字段执行 `JSON.parse()` 转换。

### 5.2 互动功能

- **点赞/收藏**：`post_like`、`post_favorite` 表防重复，计数器原子更新
- **推荐**：管理员通过 `PUT /api/post/recommend/{id}` 设置推荐标识
- **计数器**：`like_count`、`favorite_count`、`comment_count` 实时原子更新 + 定时校准

### 5.3 帖子作者信息

`PostVO` 中作者字段为 `authorNickname`、`authorAvatarUrl`、`authorCollege`（注意与资源 VO 字段名不同）。

## 六、关注系统

### 6.1 数据模型

`follow` 表包含 `follower_id`（关注者）和 `followed_id`（被关注者）两个字段，通过唯一约束防止重复关注。

### 6.2 关注操作

| 方法 | 路径 | 传参方式 | 说明 |
|------|------|---------|------|
| POST | /api/follow/add | **params** | 关注用户（followedId） |
| DELETE | /api/follow/remove | **params** | 取消关注（followedId） |
| GET | /api/follow/check | params | 检查是否已关注 → {isFollowing} |
| GET | /api/follow/following | - | 我关注的人分页 |
| GET | /api/follow/followers | - | 关注我的人分页 |

> 鸿蒙端使用 `httpClient.postWithParams()` 和 `httpClient.deleteWithParams()` 调用关注接口，对应后端 `@RequestParam` 接收方式。

### 6.3 计数器同步

用户表的 `follower_count`、`following_count` 冗余字段在关注/取关时实时原子更新，并由定时任务校准，保证数据一致性。

## 七、通知系统

### 7.1 通知模型

`notification` 表核心字段：

| 字段 | 说明 |
|------|------|
| type | 通知类型：comment/follow/like/favorite/audit |
| triggerUserId | 触发者 ID（LEFT JOIN user 表查询昵称头像） |
| receiverId | 接收者 ID |
| resourceId / postId / commentId | 关联资源（视类型而定） |
| isRead | 是否已读 |

### 7.2 通知触发场景

| 场景 | type | 触发时机 |
|------|------|---------|
| 审核结果 | audit | 管理员审核资源通过/驳回 |
| 评论回复 | comment | 资源/帖子收到新评论 |
| 关注 | follow | 被其他用户关注 |
| 收藏 | favorite | 资源/帖子被收藏 |
| 点赞 | like | 资源/帖子被点赞 |

### 7.3 通知 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/notification/list | 通知分页列表（可按 type 筛选） |
| GET | /api/notification/unread | 未读通知数量 |
| PUT | /api/notification/read/{id} | 标记单条已读 |
| PUT | /api/notification/read-all | 标记全部已读 |
| DELETE | /api/notification/delete/{id} | 删除单条通知 |

## 八、个人中心

### 8.1 我的内容

| 功能 | API | 说明 |
|------|-----|------|
| 我的资源 | GET /api/resource/user | 当前用户上传的资源分页 |
| 我的收藏 | GET /api/favorite/list | 收藏列表（含收藏时间） |

| 我的评论 | GET /api/comment/user | 当前用户发表的评论 |

### 8.2 收藏状态检查

`GET /api/favorite/check?resourceId={id}` 返回 `{isFavorite: boolean}`，用于资源详情页初始化收藏按钮状态。注意字段名为 `isFavorite`（非 `isFavorited`）。

Web 端浏览历史暂未持久化；鸿蒙端基于 `PreferencesStore` 本地键值存储实现浏览历史记录，无需登录即可查看，离线可用。

## 九、管理后台

### 9.1 统计数据

`GET /api/admin/statistics` 返回：

- 用户总数、资源总数、评论总数
- 待审核资源数
- 各分类资源分布
- 资源类型分布（document/video/code/other）

Dashboard 页面在无真实数据时使用硬编码演示数据保证图表渲染。

### 9.2 用户管理

| 操作 | API | 说明 |
|------|-----|------|
| 用户列表 | GET /api/admin/user/list | 分页 + 关键词搜索 |
| 禁用/启用 | PUT /api/admin/user/status | params: id、status（0禁用/1启用） |
| 删除用户 | DELETE /api/admin/user/delete/{id} | 级联清理其资源/评论/收藏/点赞/关注 |

禁用用户后，`GET /api/user/{id}` 公开接口将返回 404。

### 9.3 资源审核

- 待审核列表：`GET /api/admin/resource/pending`
- 审核操作：`PUT /api/admin/resource/audit`（params: id、status）
- 删除任意资源：`DELETE /api/admin/resource/delete/{id}`

### 9.4 轮播图管理

| 操作 | API | 传参方式 |
|------|-----|---------|
| 全部列表 | GET /api/admin/banner/list | - |
| 添加 | POST /api/admin/banner/add | JSON body |
| 更新 | PUT /api/admin/banner/update | JSON body |
| 删除 | DELETE /api/admin/banner/delete/{id} | 路径参数 |
| 状态切换 | PUT /api/admin/banner/status | params: id、status |

轮播图字段：`imageUrl`、`linkUrl`（非 image/link）。

### 9.5 服务卡片管理

服务卡片（FormCard）用于鸿蒙端首页推荐位展示，CRUD 与状态切换 API 同轮播图结构，路径为 `/api/admin/form-card/**`。

## 十、Web 前端实现

### 10.1 技术栈

- **框架**：Vue 3（Composition API `<script setup>` 语法）
- **UI 库**：Element Plus 2.6
- **状态管理**：Pinia（store/modules 下管理 token、userInfo）
- **路由**：Vue Router 4（含 beforeEach 守卫）
- **HTTP**：Axios 封装统一请求实例
- **构建**：Vite 5（`@` 别名指向 `src/`）

### 10.2 请求封装

`api/request.js` 创建 Axios 实例，配置：

- `baseURL`：开发环境通过 Vite 代理到 `localhost:8080`
- 请求拦截器：自动附加 `Authorization` 头
- 响应拦截器：统一处理 401（跳转登录）、业务错误提示

各业务模块（auth/resource/comment/favorite 等）按 REST 资源拆分，遵循后端 params/data 传参约定。

### 10.3 路由守卫

`router/index.js` 的 `beforeEach` 钩子实现：

- 登录判断：需登录路由未携带 token 时重定向到 `/login`
- 管理员权限：`/admin/**` 路由校验 `userInfo.role === 'admin'`
- 已登录用户访问 `/login` 自动重定向到首页

### 10.4 关键页面

| 页面 | 路径 | 说明 |
|------|------|------|
| Home | / | 首页（轮播图 + 热门资源） |
| ResourceList | /resource | 资源列表（筛选 + 搜索 + 排序） |
| ResourceDetail | /resource/:id | 资源详情（评论 + 点赞 + 收藏） |
| Upload | /upload | 资源上传（FormData） |
| UserProfile | /user/:id | 用户主页 |
| ProfileInfo | /profile/info | 个人信息编辑 |
| Dashboard | /admin/dashboard | 管理后台首页 |

## 十一、鸿蒙端实现

### 11.1 技术栈

- **框架**：HarmonyOS NEXT API 22，ArkUI 声明式 UI + ArkTS
- **架构**：双模块 HAR（`common` 公共模块 + `entry` 入口模块）
- **页面数**：22 个页面，4 个 Tab（首页/分类/搜索/我的）

### 11.2 网络层

`HttpClient` 单例模式，关键能力：

- `get<T>` / `post<T>` / `put<T>` / `del<T>`：标准 REST 方法
- `postWithParams` / `deleteWithParams`：对应后端 `@RequestParam` 接口
- **401 竞态修复**：使用 Promise 锁替代 boolean 标志，防止并发 401 触发多次登录跳转；错误信息在跳转后保留不丢失

`AuthStore` 负责 JWT token 与用户信息的持久化存储。

### 11.3 数据策略

采用 **本地 JSON 兜底 + API 刷新** 策略：

1. 页面首屏优先使用本地 JSON 数据（如 `banners.json`）渲染
2. 异步请求后端 API 获取最新数据
3. API 失败时保持本地数据，保证离线可用性

### 11.4 响应式与主题

- **断点系统**：基于 `window.getWindowSize()` + `mediaQuery` 实现 5 级断点（XS/SM/MD/LG/XL），不可使用 `display` API（模拟器不可靠）
- **双主题**：亮色（靛蓝毛玻璃）/ 深色（极简黑白）完全独立色板，通过 `@StorageLink('isDarkMode')` 订阅切换
- **毛玻璃性能分级**：`BlurPerformance` 根据设备性能与滚动状态动态降级（HIGH/LOW/NONE）

### 11.5 服务层

鸿蒙端在 API 层之上封装了 Service 层，负责本地缓存与 API 桥接：

| 服务 | 职责 |
|------|------|
| ResourceService | 资源搜索/分类，本地 JSON 兜底 |
| FavoriteService | 收藏/浏览历史，基于 PreferencesStore 持久化 |
| CommunityService | 帖子本地管理 + API 桥接 |
| RecommendService | 基于年级/收藏/浏览的推荐算法 |
| CurriculumService | 课程推荐数据 |
| GradeService | 年级设置 |
| TtsService | 文本朗读 |
| ShareHelper | 分享功能 |

## 附录：关键约定速查

### 传参方式约定

| 接口类型 | 传参方式 |
|---------|---------|
| 登录/注册/更新信息/创建资源/帖子 CRUD/轮播图 CRUD | JSON body（FormData 用于文件上传） |
| 评论/收藏/关注/审核/状态切换 | params（对应 `@RequestParam`） |
| 删除操作 | 路径参数 `{id}` |

### 分页约定

- 请求参数：`pageNum`、`pageSize`（非 page/size）
- 响应字段：`records`、`total`（非 list）

### 状态值约定

- 资源状态：0 待审核 / 1 已发布 / 2 已驳回
- 用户状态：0 禁用 / 1 启用

### 字段命名约定

- 资源作者：`uploadNickname`、`uploadUsername`、`uploadAvatar`
- 用户头像：`avatarUrl`
- 轮播图：`imageUrl`、`linkUrl`
- 收藏检查：`isFavorite`
- 关注检查：`isFollowing`
- 帖子作者：`authorNickname`、`authorAvatarUrl`、`authorCollege`
